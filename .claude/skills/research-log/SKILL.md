# 日志与规划（research-log）

| 目录 | 记什么 | 节奏 |
|---|---|---|
| `日志/` | 当天**动作与结果**：从哪拿到什么、踩了什么坑、实测数字 | 一天一篇，平铺 |
| `规划/` | **三个月后还要回看**的：建议、方向决策、评估结论、迁移备忘 | 按主题一篇 |

判断：**"三个月后还要回头看吗？"** 要 → 规划；只是当天经过 → 日志。

## 1. 读多少算够（省 token 的硬规则）

- **用户没让写，就不要读**这两个目录里的任何文件。
- 写日志：只读**最近 1 篇**的 `## 待完成`（要承接时才读；没有就算了）。**不要通读历史日志。**
- 写规划：按**文件名**找同主题（`ls 规划/ | grep 关键词`），命中就读那 1 篇；没命中就新建。**不要为了找主题把 `规划/` 读一遍。**
- 需要某段历史时按需读，一次 1 篇，读完就停。

## 2. 命名与去重

- 日志：`日志/YYYY-MM-DD-标题.md`；标题用 `·` 连接两个概念，文件名不加空格。
- 规划：`规划/YYYY-MM-DD-主题.md`，日期取**首次撰写日**；同主题并入原文件、保留原日期。
- **同一天只有一篇日志**：动笔前 `ls 日志/<今天>-*`；有 → **扩写那一篇**，没有 → 新建。扩写**不改文件名**（会打断指向它的链接）。

## 3. 正文写什么

| 段落 | 内容 | 必要性 |
|---|---|---|
| `**环境**` | 机器 / 工具版本 / 模型 / 数据规模 | 涉及具体环境时写 |
| `## 1.` … `## N.` | 按**主题**分章（不是按时间），标题写结论 | 必写 |
| `## 发现的问题` | 见 §4 | 有问题就写 |
| `## 待完成` | `- [ ]` 复选框 | 必写 |
| `## 相关` | 上一篇 / 相关文件 / 规划里的详版 | 必写 |

正文记**动作与结果**（从哪下载、字节数、踩坑、实测数字、改了哪些文件）；**决策与评估放 `规划/`**，日志里留一行指针。

## 4. 发现的问题（流水账里最值钱的部分）

**现象 → 根因 → 证据**三段式；证据贴**原始输出**（报错原文、命令、日志行），不转述。
按严重程度排，最严重标 `【最严重】`。数字必须实测，不确定标 `<!-- 待确认 -->`。

## 5. 禁止

- 编造数字、路径、命令输出
- 把对话原文整段贴进来（要提炼）
- 日志建子目录、改已有日志文件名
- 把该进 `规划/` 的长期内容只留在日志里

## 6. 写完

1. 更新根 `README.md` 里对应**文件夹行**的「最后更新」（只到文件夹层，不建逐篇清单）。
2. 告诉用户：落在哪个目录、文件名与 H1 是什么、是**新建**还是**扩写**；规划要说清新建了哪个主题或并入了哪篇。
3. 附一句还没解决的事（`## 待完成` 就是下次起点）。

模板：`templates/日报.md`、`templates/规划.md`。
