# 索引树（folder-readme）

**索引只记两件事**：这块有什么、它是干什么的。不记"这次改了什么"（那是日志的活）。

## 1. 树的形状

```
README.md              根：有哪些块 / 每块干什么 / 指到哪个子 README
  ├── <目录>/_index.md    子：这块有什么、现在到哪了
  └── 根目录散件          不属任何块的文件，也登记在根
```

- **子之间同构，根不同构**：根是地图，不含状态、不含叶子细节。
- 子 README 叫 `_index.md`（都叫 `README.md` 会让双链歧义）。
- **直辖目录**（本项目的 `日志/`、`规划/`）：不建子 README，由根直接管辖；根里写明"没有子 README"，**只索引到文件夹层，不逐篇列文件**。

## 2. 两类文件：计划 / 数据

| 类型 | 是什么 | 浏览时 |
|---|---|---|
| **计划文件** | 日志、规划、方案、决策、`_index.md` | **读** |
| **数据文件** | 语料、向量、卡片、缓存、构建产物 | **不读**（可重建，或该由脚本读） |

数据文件在 README 里只记一句「数据 ×N，可重建」，不逐条列——几千个产物进索引等于把索引变成第二个数据目录。

## 3. 子 README 写什么（五节，按此顺序）

| 节 | 内容 |
|---|---|
| 1. 这个文件夹是什么 | 一句话定位（它在整条链路里的位置） |
| 2. 当前工作状态 | 问"现在到哪了"只看这节 |
| 3. 文件清单 | **计划文件逐条**：文件名 + 一句作用；数据文件只写 ×N |
| 4. 建议阅读顺序 | **只排计划文件** |
| 5. 相关 | 上位指针（纯文本路径）、同层相关块 |

> 第 3 节标出哪些是计划文件，第 4 节就只排它们；数据文件不许出现在第 4 节。

**脚本速查**：含 `.py` 的目录，在 README 里逐行写 `- 文件名 —— docstring 首句`。
`__init__.py` 不记；子目录的脚本由子目录自己记。

## 4. 改完做什么

1. 新建 / 删除 / 改名计划文件或 `.py` → 改对应子 README 的清单；文件夹**用途**变了 → 改它的第 1 节。
2. 直辖目录（`日志/`、`规划/`）只改根里那一行的「最后更新」，**不建逐篇清单**。
3. 跑 `python scripts/check_tree.py --vault .`，全绿再报告。

自检查三件：悬空双链、从根走不到的孤岛文档、README 的「脚本速查」与磁盘 `.py` 是否一致。

## 5. 根 README 的五节

1. 索引树（表格：文件夹 / 干什么 / 它的 README / 最后更新）
2. 直辖文件夹（目录级用途 + 阅读时机，不列文件）
3. 根目录散件
4. 建议阅读顺序（只排计划文件与入口）
5. 不在树上的目录（每项写"为什么不列"）

## 6. 入口那一句话

树是给新会话用的，而新会话不会自己找树。项目根要有 `AGENTS.md` / `CLAUDE.md`，至少写清：**有哪几块**、**动手前先读那块 `_index.md`**、**改完回写**。
