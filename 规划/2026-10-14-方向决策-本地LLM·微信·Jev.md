> 2026-10-14 记录。这是三条外部建议/方向的**决策基准**（谁建议、评估结论、怎么落地、归谁），需要长期参考；当日流水账见 `日志/2026-10-14-...`。

## 0. 三条方向的总体判断

| 方向 | 契合度 | 改动量 | 建议 | 归谁 |
|---|---|---|---|---|
| 本地 LLM（12G 显存机器）| 中（可选后端）| 小（改 base_url）| 当"备胎/答辩自主"，14B 量化，别硬上 32B | 前端（面板加切换档）|
| 微信助手 | 高（愿景）| 中偏大 | 放前端改造之后，共用统一后端接口；**注意微信合规** | 前端 + 接口上下文 |
| Jev 决策模型 | 高（判别侧）| 小–中 | 放"论文筛选/判断"的决策层；**先社区复现、后自训** | 算法 + 接口上下文 |

## 1. 本地 LLM（有人建议：一台"显存+大内存+几 T 盘"的机器）

- **事实纠正**：阿里千问主流量级是 7B/14B/32B/72B，没有正好"27B"档；12G 显存跑 32B（FP16 权重约 64GB）放不下，量化(Q4~18GB)+CPU offload 勉强，生成 2–5 token/s。12G 理想是 **14B 量化**；舒服跑 32B 要 **24GB+**。
- **契合**：LLM 用点在 L3/L4/L5（查询规划/簇命名/答案/引用校验），当前走移动云 MaaS API（`llm.py:make_client` 从 `config.yaml` 的 `base_url` 构造 dasc Client）。接本地 = `base_url` 指 vLLM/Ollama OpenAI 兼容端点，**引擎一行不动**。成本在部署运维。
- **反面**：本地 32B 量化效果大概率不如云端 `deepseek-v4-flash`，还慢；现状 API token 成本已极低（`max_input_chars 8000` 闸 + fix-prefix 缓存）。为"本地化"牺牲质量要看目的——**比赛"自主可控"是加分项，值得；省钱不划算**。
- **判定**：加，但作为**可选后端**（cloud 主、本地备），不替换。
- **另注**：内存大 + 盘大的真正大收益 = 全库向量拼大矩阵 GPU 提速（算法档），比 12G 跑本地模型更划算。

## 2. 微信助手（愿景：做成微信，加群聊天 + 群里发周报）

- **契合**：引擎完全可复用，微信机器人只是**换前端接入层**（消息 → 引擎 → 答案；周报群发 = `update_arxiv_weekly` 产物 + 定时推送）。**引擎零改动**。
- **改动量**：中偏大。前端改造（HTML/JS + 账号 + MySQL）之外**再开一条接入线**：消息接收/会话绑定（微信 ID ↔ 会话）、长回答分片、并发、主动群发调度（自动化 cron 可参考）。架构上建议**统一后端 API**，Web 前端与微信机器人共用一接口。
- **⚠️ 两个坎**：
  1. **平台合规**：个人微信做机器人加群自动回复违反平台条款有**封号风险**，且外挂 hook（wechaty 等）多数已失效。合规路径 = 企业微信/公众号/小程序；比赛可接受"仿真演示"（聊天窗口模拟）。
  2. **账号体系**：前端改造正在做"每账号独立 API 配置 + 会话"，微信天然按 ID 隔离 → **正好共用这套账号/会话设计**。
- **判定**：值得做，**放前端改造之后**。

## 3. Jev 决策模型（TypeSafe System One；JEV 为 TypeSafe 最近推出的决策模型）

### 3.1 Jev 是什么 / 付费与否

- 不讲自然语言，**做快速结构化决策**（Choice/Score/Noul 三原语 + 概率 + 置信度），70–500ms，宣传"不幻觉"。代码直接用结果、不用解析。
- **付费云 API**：官方 `$42/Btok = $0.042/Mtok`（每百万输入约 0.3 元），**只按输入 token 计，输出免费**，64k 上下文。第三方入口（Cloudflare Workers AI / OpenRouter）调同一真实 API。
- **没有本地/自托管版**（官方不开放权重、不可微调 LoRA）；独立于"12G 本地大模型"方向。

### 3.2 社区复现

- 上轮误判"无开源"——实际 GitHub 上 openjev 系 143 仓库。较成型：
  - `razorback16/openjev`（703★，DiffusionGemma 26B-A4B，需 **24GB 显存**/16GB+ 内存——本机跑不动）
  - `openJev-verdict-2.0`（294★，ModernBERT 151M，**CPU 可跑**，Apache-2.0）——已下载试用
- ⚠️ 社区复现质量参差、无官方评测背书，**当基线可以，别直接进生产/答辩主链**。

### 3.3 与本项目契合点（判别侧，与 LLM 生成互补）

| 项目环节 | 现状（deepseek-flash） | Jev 替换/增强 |
|---|---|---|
| 检索候选**筛选**（论文筛选）| 无显式过滤 | Noul/Choice：每篇"是否相关"，按概率过滤+精排 |
| 路由 `router.py`（GLOBAL/LOCAL）| LLM 判 | Choice 更稳更快 |
| 引用校验 `verify.py`（真/假）| LLM 判 missing/unsupported | Noul 二分类，天然匹配 |
| **周报增量筛选**（每周新增）| 无 | Noul/Score 过滤哪些入库/上推荐 |
| parse_query 意图分类 | LLM JSON | intent 用 Choice 可换；keywords 抽取仍留 LLM |
| 簇命名/答案生成 | deepseek | **不适合**（Jev 不生成文本），保留现有 |
