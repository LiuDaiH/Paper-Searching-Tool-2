# 周报库接入大创算法 · 规划（补引用图 + 重训 RF）

> 目标：让 arXiv 周报库也能用上大创那套「图相关」检索算法——`relation/共同来源`、
> `Streit-Garg(MPS)`、`rlRAG(RF 未来被引重排)`。现状是周报只继承了**不依赖引用网络**
> 的检索（词级/向量/改写/路由/聚类/verify），图相关三样因**缺引用图 + 缺训练模型**不可用。
> 时间：2026-10-02 拟定。口径与决策源见 `2026-10-02-规划-接入arXiv周报与发布.md`。

---

## 1. 为什么周报缺图（数据差异，已在 §设计确认）

| | 会议库（24+25） | 周报（arXiv） |
|---|---|---|
| 引用边 | 有：`.src` 解包 + srcmap + agg_refs → `paper_refs.json` | **无**：`papers.jsonl` 只有 `citations` 整数，无 referenced 列表 |
| `.src` 源码包 | 有（导师库/A 侧） | 无（arXiv 元数据） |
| 可复用引用源 | 内部源码 | 需**外部**（Semantic Scholar 已测可达，429 需退避；OpenAlex 对 arXiv 支持差） |

⇒ 补引用图是地基；RF/MPS 数据依赖它。

## 2. 大创算法的数据依赖（现会议库实现 ↓）

- `rlr.py::RFRanker` → `future_rf.pkl` + `mobile_corpus_vectors.npz` + `global_mean.npy` + `cite_graph.pkl(forward)` + `years/early_ids`。
- `mps.py::compute_key_path` → `rl_prep/cite_graph.pkl(forward/reverse)` + `coverage.pkl(paper2cluster/icf)`。
- `co_cite`/`relation` → 被引 arXiv 边（`paper_refs`）。

**对周报，需重建每一块**：引用图 → 向量 npz/mean → coverage(聚类) → 重训 RF。

## 3. 分步方案（每步可独立验证）

| 步 | 做什么 | 产出 | 验证 |
|---|---|---|---|
| **R1 补引用图** | `scripts/fetch_arxiv_refs.py`：Semantic Scholar `paper/batch`（≤100/批）拉每篇 `references[].arxivId`，**增量断点续跑** + 429 退避 | `workspace/depgraph/paper_refs_arxiv.json` + `cite_graph_arxiv.pkl`(fwd/rev) | `--limit` 小批跑通、边数>0、断点续跑 |
| **R2 建周报 rl_prep** | 从 P3 的 `arxiv_vectors/` 导 `mobile_corpus_vectors_arxiv.npz` + `global_mean.npy`；cite 边整理 | `workspace/arxiv_rl/rl_prep/` | 向量 4369×1024、mean 尺寸对 |
| **R2b coverage** | 周报预聚类 → `coverage_arxiv.pkl`(paper2cluster/icf)（供 MPS） | 同目录 | ⚠️ 依赖周报聚类，未做前 MPS 明确报「缺 coverage」 |
| **R3 重训 RF** | `scripts/export_future_rf_arxiv.py`：仿 dasc，`year` 分早/晚批 + future 标签（早论文是否被晚批引用）→ 训练 RF + PCA | `workspace/arxiv_rl/future_rf_arxiv.pkl` | `--limit` 用已向量子集跑通，正样本>0 |
| **R4 接线** | 泛化 `rlr.RFRanker` / `mps.compute_key_path` 支持数据源切换（config `arxiv_rl` 段）；`subcluster`/`app` 在 arXiv 源时读周报数据 | 前端/run_qa 在 arXiv 源可用 relation/Streit-Garg/rlRAG | 自检 + 小样本问答 |

## 4. 数据源与红线

- **引用源 = Semantic Scholar**（实测可达；无 key 下 429 用指数退避 + 慢节流；`--limit`/断点续跑便于分批完成全量）。OpenAlex 对 arXiv 支持差（`filter=arxiv:` 400、不收录 arXiv DOI），不用它做引用边。
- **年份批次**：周报 `papers.jsonl` 有论文自定义 `year`（2018–2026）与 `first_seen`（入库周）。RF 的 early/late 取 `year` 时间留出（早批 vs 晚批被引），标签 = 早批论文是否被晚批引用。
- **红线不变**：三态只表述铺开/新进/单会；无退潮/下降/衰退。引用层只是「该学/该引」的排序信号，不改变热点三态口径。
- 数据缺失 = 明确报「未运行/缺数据」，绝不假装空结果（沿用签名病原则）。
- 周报是外部只读库；所有新产物落 `workspace/`（可重建、不入库）。

## 5. 与发布物（P3）的关系

`weekly_arxiv/` 发布物**只含向量+meta+统计**，**不含引用图/模型**（避免包过大 + 图数据属中间物）。
若别人也要图类检索，须由你侧保留服务（单体 Streamlit，详见 `2026-10-02-规划-接入arXiv周报与发布.md` §2）。

## 6. 未决 / 风险

- **外部引用数据源（实测 2026-10-02，硬阻塞）**：Semantic Scholar 无 key 时 **429 极频繁**（单条 GET 3 篇即超时），单条 8 全量 4,369 篇需数小时且不稳定；S2 **batch** 端点不识别 `ARXIV:` 前缀（返回非 arXiv record、refs=0）。OpenAlex 无 `arxiv:` filter（400）、对 arXiv 记录的 `referenced_works` 为空。⇒ **全量引用图需①配 Semantic Scholar API key（`apis.api_key_env`）或②受控网络**；R1 脚本已做成可配 key + 断点续跑，凭 key 一次补齐。
- **coverage（周报聚类，R2b）**：MPS 的 paper2cluster/icf 依赖周报主题聚类，未做前 Streit-Garg 在周报上**诚实降级**（`key_path_error`，不假装空结果）。
- **RF 训练信号**：周报 `year` 时间轴 vs 会议库的 2024→2025 时空留，标签口径需对齐；无 future-cite 信号时明确报错。
