# 接口契约 · 前端 ↔ 算法（API v1）

> 长期参考。**改接口先改本文档**，再改 `hotspot/api/contract.py`；两者不一致时以代码为准并立刻回来补文档。
> 落地代码：`hotspot/api/`（契约 `contract.py` / 引擎 `engine.py` / HTTP `http.py`）。
> 自检：`python scripts/check_api.py`（离线、秒级，全绿才算没改坏接口）。

## 0. 一句话

**前端只准 import `hotspot.api`；算法随便改内部，只要 `Engine.ask` 的返回字段还在。**

```
HTML/CSS/JS  ──HTTP──┐
                     ├─▶ hotspot.api.Engine ──▶ L1 语料 / L2 结构 / L3 卡片 / L4 检索 / L5 推理
Streamlit    ──直调──┘        （唯一编排处，无会话状态）
```

## 1. 改造前：耦合到底有多深（2026-10-18 统计）

改造前 `hotspot/ui/app.py`（844 行）直接 import **11 个模块 / 19 个符号**，还自己实现了一整套编排：

| 类别 | 具体 | 数量 |
|---|---|---|
| 直接 import 的模块 | `config` `corpus` `direction` `llm` `subcluster` `retrieval.router` `retrieval.rewrite` `retrieval.assemble` `reasoning.answer` `reasoning.verify` `schema` | **11** |
| 直接调用的符号 | `load_config` `paths_from` `open_corpus` `arXivCorpus` `select` `make_client` `parse_query` `subcluster_adaptive` `_run_mps` `route` `REFUSE_REASON` `rewrite` `assemble` `generate_answer` `parse_claims` `verify_claims` `build_answer` `Answer` `Route` | **19** |
| 必须认识的内部数据结构 | `Paper` / `Pool` / `Answer` / `Verdict` / `Context` / `Route` | **6** |
| 必须认识的磁盘格式 | `workspace/cards/card_*.json`、`key_path` 字典（12 个键） | **2** |
| UI 里自己实现的编排 | 意图路径、兜底路径、卡片挑拣、证据挑选、引用 deref、追问、关键路径画图 | **7 段** |

后果很具体：

1. 前端要改成 HTML/JS，就得把这 7 段编排**再用 JS 写一遍**（或者让浏览器调 Python 内部函数）——两套编排必然漂移。
2. 算法改一个函数签名，前端静默崩。
3. 每个新 agent 上手要先读 844 行 UI + 8 个算法文件，token 全花在"看懂"上。
4. 顺手发现的 bug：`_maybe_keypath` 里写的是 `from .subcluster import _run_mps`（应为 `..subcluster`），
   被 `except` 吞掉 ⇒ **兜底路径的关键路径从来没生效过**。这类"耦合导致的静默失败"只有搬走编排才看得见。

## 2. 改造后：只剩 2 个接口

| 接口 | 方法 | HTTP | 干什么 |
|---|---|---|---|
| 能力/参数自描述 | `Engine.meta()` | `GET /api/meta` | 语料概况 + **参数表**（前端自动生成设置页）+ 能力开关 + LLM 默认值 |
| 问一次 | `Engine.ask(req)` | `POST /api/ask` | 新问题/追问 + 参数 + 每用户 API 配置 + 引用 + 图谱 + token 用量 |
| 探活（非业务） | — | `GET /api/health` | 运维/联调用 |

一条请求里装下的东西（**不要**再拆成 `/api/route`、`/api/retrieve`、`/api/graph`、`/api/usage`）：

- 问题与模式（新问 / 追问）
- 数据源（会议 / arXiv）
- 每用户的 `base_url` / `model` / `api_key`
- 白名单内的检索参数
- 返回：答案文本、路由、引用（**已 deref 标题/年份/链接**）、主题簇（结构化）、
  关键路径图（nodes/edges）、引用校验明细、token 用量、降级提示

为什么不再拆细：拆细意味着前端要按顺序调 4–5 个接口、自己维护中间状态，
那就等于把编排搬回前端——正是这次要消掉的东西。

### 不属于接口层的东西（别往引擎里塞）

| 事情 | 归谁 | 为什么 |
|---|---|---|
| 账号 / 密码 / 多租户 | 前端 | 引擎无会话状态，请求带什么用什么 |
| 会话列表、消息持久化 | 前端 | `history` 是请求数据；现在 Streamlit 存 `workspace/exports/sessions.json`（`hotspot/ui/store.py`），未来换 MySQL |
| 页面、图表库、配色 | 前端 | 引擎只给 `nodes/edges`，画成 plotly 还是 d3 由前端定 |
| 引用图排版、进度条动画 | 前端 | 引擎只发 `stage` 事件 |

## 3. 请求：`AskRequest`

`POST /api/ask`，`Content-Type: application/json`。

| 字段 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `question` | string | ✅ | — | 问题原文，上限 2000 字（超了截断并给 warning） |
| `source` | string | | `meeting` | `meeting`（会议 24+25）/ `arxiv`（周报） |
| `mode` | string | | `new` | `new` 重新检索 / `followup` 基于历史 |
| `history` | array | | `[]` | 历史消息，**只有 followup 用**；最多 40 条 |
| `history[].role` | string | ✅ | — | `user` / `assistant` |
| `history[].text` | string | ✅ | — | 消息正文 |
| `history[].citation_ids` | string[] | | `[]` | 该轮引用的论文 id —— **追问时服务端据此把前文论文摘要并进上下文** |
| `llm.base_url` | string | | cfg | 该用户的端点 |
| `llm.model` | string | | cfg | 该用户的模型 |
| `llm.api_key` | string | | cfg | 该用户的 key；**响应永不回显**，不入日志 |
| `params` | object | | `{}` | 白名单参数（见 §5），越界/未知键 → 400 |
| `dry_run` | bool | | `false` | 不调真 LLM，只跑离线链路（前端无 key 时把界面跑起来用） |
| `include_graph` | bool | | `true` | 是否计算/返回关键路径图 |
| `stream` | bool | | `false` | **仅 HTTP 层识别**（不传给引擎）：`true` 走 SSE |

最小请求：

```bash
curl -X POST http://127.0.0.1:8000/api/ask \
  -H "Content-Type: application/json" \
  -d '{"question":"2025 RLHF 方向最火的是什么？","source":"meeting"}'
```

> `llm.base_url` 推荐填 **base URL**（例如 `https://…/v1`）；填完整的
> `…/v1/chat/completions` 也会被规范成 base URL，客户端再拼一次。
>
> `llm.api_key` 省略时，服务端会使用 `config.yaml` 的 `llm.api_key`
> 或显式配置的 `llm.api_key_env` 指向的环境变量；`meta.llm.has_server_key`
> 报的就是这条路径是否可用。请求里显式传 key 时，环境变量不会覆盖它。

追问（把上一轮回答里的 `citations` 里的 paper id 存下来带回去）：

```json
{
  "question": "那第二篇具体怎么做的？",
  "mode": "followup",
  "history": [
    {"role": "user", "text": "2025 RLHF 方向最火的是什么？"},
    {"role": "assistant", "text": "…… [P:2410.01234]", "citation_ids": ["2410.01234"]}
  ]
}
```

## 4. 响应：`AskResponse`

| 字段 | 类型 | 说明 |
|---|---|---|
| `contract_version` | string | 契约版本，当前 `"1"` |
| `request_id` | string | 排障用（**不要**塞进 prompt） |
| `source` / `mode` | string | 回显请求 |
| `route` | string | `global` 全局热点 / `local` 局部事实 / `followup` 追问 / `refuse` 拒答 / `error` 内部错误 |
| `refused` | bool | 是否拒答 |
| `refuse_reason` | string | 拒答口径（可直接展示） |
| `answer.text` | string | 答案正文，引用标记形如 `[P:<paper_id>]` / `[C:<cluster_id>]` |
| `answer.n_filtered` | int | 被过滤的无据陈述数（**要显示给用户**，不能悄悄吞） |
| `answer.verdicts[]` | array | `{status, text, detail}`；`status` ∈ `supported` / `unsupported` / `missing_id` / `no_citation` |
| `answer.citations[]` | array | **已摊平**：`{id, kind, title, label, venue, year, abstract, arxiv_id, url}` |
| `topics[]` | array | 主题簇：`{cluster_id, label, core, size, venue_counts, year_counts, representative_id, representative_title, member_ids}` |
| `graph` | object\|null | `{nodes[], edges[], algo, seed_count, value, delta, conn, covered_clusters}` |
| `graph.nodes[]` | array | `{id, title, step, cluster, new_cover, covered_so_far}`（`covered_so_far` 是累积 ICF，不是篇数） |
| `graph.edges[]` | array | `{source, target, kind}`；`kind` = `chain`（阅读序主链）/ `cite`（真实引用依赖） |
| `usage` | object | `{llm_calls, tokens_in, tokens_out, cache_hits, failures, cost_yuan, elapsed_s, stages}` —— **实测值**，来自 LLM 客户端计数器 |
| `warnings[]` | string[] | 降级/截断提示，前端折叠展示即可 |
| `error` | object\|null | `{code, message}`，与 `route=error` 同时出现 |

三条渲染约定（省前端的事）：

1. **引用不用再查语料**：`citations[].title` 已填好；`arxiv_id` 有值时 `url` 也填好。
2. **主题簇不用解析 markdown**：`topics[]` 是结构化字段，怎么排版前端定。
3. **图不用懂算法**：拿到 `nodes/edges` 直接画；`chain` 画实线、`cite` 画虚线即可。

## 5. 参数表（`meta.params` 自动给，13 个）

前端**不要硬编码**这些字段——`GET /api/meta` 的 `params[]` 里带 `key/label/group/type/value/min/max/step/default/help`，
直接循环生成表单。加参数时只需改 `hotspot/api/contract.py` 的 `PARAM_SPEC`（+ `config.yaml` 默认值）。

| key | 类型 | 默认 | 范围 | 分组 | 作用 |
|---|---|---|---|---|---|
| `top_k_local` | int | 8 | 1–50 | 检索 | 局部题现场取几篇摘要 |
| `top_k_vector` | int | 50 | 0–500 | 检索 | 语义召回候选池 |
| `top_k_direction_fts` | int | 1000 | 100–20000 | 检索 | 方向召回上限 |
| `top_query_direct` | int | 8 | 0–50 | 检索 | 关键词直投篇数（救稀疏主题） |
| `llm_router` | bool | true | — | 检索 | LLM 智能路由（关掉更快更省） |
| `query_rewrite` | bool | true | — | 检索 | 检索前 LLM 改写 |
| `followup_rounds` | int | 3 | 1–10 | 追问 | 追问读取几轮对话 |
| `followup_papers` | int | 4 | 0–10 | 追问 | 追问带入几篇前文论文（0=不带） |
| `max_topics` | int | 6 | 1–12 | 展示 | 最多命名/展示几个主题簇 |
| `max_evidence` | int | 8 | 1–20 | 展示 | 进上下文的证据论文数 |
| `evidence_chars` | int | 300 | 80–800 | 展示 | 每篇摘要保留字符 |
| `rlrag` | bool | false | — | 算法开关 | RF 未来被引重排 |
| `streit_garg` | bool | true | — | 算法开关 | 算关键路径并返回引用图 |

**校验口径**：未知 key、类型错、越界一律 `400 bad_request`，**不静默忽略**
（静默忽略会让前端以为参数生效了——这是本项目最反感的失败模式）。

## 6. 流式（进度）

同一个路由，请求体加 `"stream": true`，响应变 `text/event-stream`：

```
: connected

data: {"type":"stage","stage":"parse","label":"意图解析/改写","cur":null,"total":null,"elapsed":0.42}

data: {"type":"stage","stage":"verify","label":"校验引用","cur":3,"total":7,"elapsed":9.1}

event: result
data: { …完整 AskResponse… }
```

约定：

- `stage` 只有 5 个：`parse` → `retrieve` → `name` → `answer` → `verify`（顺序即阶段顺序）；
- **`cur/total` 都为 null 时不要画进度条**，只显示阶段名 + 已耗时（引擎不给假百分比）；
- 出错时发 `event: error` + `{"error":{...}}`；
- 前端用 `fetch` + `ReadableStream`（`EventSource` 只支持 GET，不适合）。

Streamlit 版本走的是同一个回调（`Engine.ask(req, on_event=...)`），不是另一套逻辑。

## 7. 错误码

| code | HTTP | 场景 | 前端怎么办 |
|---|---|---|---|
| `bad_request` | 400 | 参数/字段不合法、JSON 坏 | 提示具体 message（中文，可直接展示） |
| `no_api_key` | 400 | 既没传 `llm.api_key`，服务端也没配 | 跳到"API 配置"页 |
| `corpus_unavailable` | 503 | 语料路径缺（G 盘/测试集未挂） | 提示换数据源或检查挂载 |
| `internal_error` | 500（适配层崩溃）/ 200（引擎兜底） | 兜底。引擎兜底时**仍是完整响应**，看 `route=="error"` + `error` | 展示 `error.message` 与 `request_id` |
| `not_found` | 404 | 路由不存在 | — |

## 8. 前端接手指南（给做 HTML/JS 的同学）

1. 起服务：`python scripts/run_server.py --port 8000 --web web`
2. 拉 `GET /api/meta` → 用 `sources` 填数据源下拉、用 `params` 生成设置页、`capabilities` 决定按钮是否可用。
3. 提问：`POST /api/ask`（可加 `stream:true` 画进度）。
4. 渲染：`answer.text`（markdown）+ `answer.citations`（来源列表）+ `topics`（卡片）+ `graph`（图）。
5. 追问：把每条 assistant 消息的 `citations` 里 `kind=="paper"` 的 id 存进 `citation_ids`，下次带 `history`。
6. 账号系统：`llm` 三个字段从该用户的设置表读；引擎不关心谁在问。
7. 参数调优页：把 `params` 表单值原样放进 `params` 字段即可，**不需要知道这些参数在算法里叫什么**。

`web/index.html` 是一份**最小参考前端**（原生 JS，无构建），可以直接改，也可以整页删掉重写。

`requirements.txt` 不需要为接口层加任何依赖——HTTP 层是标准库。

## 9. 算法接手指南（给做模型/提速的同学）

- 你可以在 `subcluster.py` / `verify.py` / `rlr.py` / `structure/` 里**随便改**，只要不破坏
  `Engine.ask` 返回的字段（§4）。
- 新增输出（比如模型对比分数、新的图类型）：在 `hotspot/api/contract.py` 里**加带默认值的字段**，
  在 `engine.py` 里填上。**只增不改**，前端不用动就会忽略多余字段。
- 新增可调参数：`PARAM_SPEC` 加一行 + `config.yaml` 给默认值 → 前端设置页**自动**出现，不用通知前端。
- 别在 `hotspot/api/` 里写算法；这里是"翻译层 + 编排"，算法逻辑请留在 L1–L5。

## 10. 兼容与迁移

| 事项 | 现状 |
|---|---|
| 旧 Streamlit 前端 | 保留，已改为调 `Engine`（`hotspot/ui/app.py` 只剩渲染与会话存储） |
| 启动方式 | Streamlit：`streamlit run scripts/run_ui.py`；新前端：`python scripts/run_server.py` |

| 旧调用方（`eval/`、`scripts/run_query.py`） | 不受影响，它们仍可直接用 L1–L5（接口层是**新增**，不是替换） |
| 会话/API 配置 | 仍在 `workspace/exports/sessions.json`、`workspace/settings.json`（`hotspot/ui/store.py`），等账号系统接管 |
| 鉴权 | 接口层**没有鉴权**（内网/演示用）。上线前由前端在反向代理或网关加，不要在引擎里加密钥逻辑 |

## 11. 已知限制（诚实清单）

- **SSE 无断线重连**：断了就重发请求；引擎本身是幂等读，重发安全（LLM 有缓存）。
- **`api_key` 明文经 HTTP 传输**：只适合本机/内网；公网必须 HTTPS + 网关。
- **`usage.cost_yuan` 是估算**：单价取自 `config.llm.cost_per_1m_*`，token 数是实测。
- **追问不做引用校验**（对话连续性优先）：`verdicts` 为空是预期的，不是漏了。
- **一次请求一条答案**：不做多轮自动追问/工具调用。
- **`dry_run` 只跑离线检索**：答案正文为空并带 warning；前端应显示“未调用 LLM”的离线提示，真实可用性仍需 key。
