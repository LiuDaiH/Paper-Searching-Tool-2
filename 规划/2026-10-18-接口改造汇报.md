# 接口改造汇报（2026-10-18）

> 分支 `refactor/decouple-api` · PR [#1](https://github.com/w16073888/Paper-Searching-Tool-2/pull/1) · 4 个 commit
> 本文是给组里看的**汇报版**；字段级细节在 `2026-10-18-接口契约-前端与算法.md`，不在这里重复。

## 一句话

把「前端 ↔ 算法」之间散着的 **11 个模块 / 19 个 import 符号**，收成 **2 个接口**（`meta` / `ask`）；
编排从 844 行的 UI 里搬进服务层；并用**三个全新 AI 会话按角色实测**，证明新人照文档能直达目标文件、不起子代理——测试过程中还挖出并修掉 3 个真 bug。

## 1. 改造前的问题（不是代码丑，是改不动）

`hotspot/ui/app.py` 844 行里，约 500 行不是界面，而是它自己开着整条管线：

`方向选择 → 子聚类 → 并行命名 → 拼卡片 → 挑证据 → 生成答案 → 逐条校验 → 画关键路径`

直接后果：

| 后果 | 具体表现 |
|---|---|
| 前端重构要重写一遍编排 | 换 HTML/JS 得把这 500 行用 JS 再写一次，两套必然漂移 |
| 算法改名，前端崩 | 11 个模块的签名都是隐式契约，没有任何地方写着"哪些能用" |
| Agent 上手成本高 | 先读 844 行 UI + 8 个算法文件，token 花在"看懂" |
| 错误被吞 | 编排里包着 `try/except`，`_maybe_keypath` 的导入 bug 静默失效了很久（见 §4） |

## 3. 接口对比

| 维度 | 改造前 | 改造后 |
|---|---|---|
| 前端要 import 的模块 | 11 | **0** |
| 前端要调的符号 | 19 | **2**（`meta` / `ask`） |
| 前端要认识的内部结构 | 6 个 dataclass + 卡片 JSON + key_path 字典 | **0**（引用已补标题/年份/链接，图已摊平成 nodes/edges） |
| 两套前端是否共用逻辑 | 否 | **是**（Streamlit 与 HTTP 同一个 Engine） |

一条请求里带完：问题、数据源、追问历史、每用户 `base_url/model/key`、检索参数；
一条响应里给完：答案、路由、引用（已 deref）、主题簇、关键路径图、校验明细、token 用量、降级提示。

**为什么不拆成 `/route`、`/retrieve`、`/graph`**：拆细就要前端自己维护中间状态，等于把编排搬回前端。

## 4. 实验验证

### 4.1 接口自检：32 项断言全绿

```
$ python scripts/check_api.py
[1] 契约往返        16 项 ok   （字段解析 / 参数归一 / key 不回显 / 响应形状）
[2] 检索语义         3 项 ok   （长句 AND 必空 / 并集必召回 / 空查询不崩）
[3] 真引擎 meta      1 项 ok   （数据缺失也要降级返回，不许崩）
[4] HTTP 冒烟        12 项 ok  （health / meta / ask / 非法参数 400 / 坏 JSON 400 / 404 / SSE）
✓ 接口自检全绿（契约 / 参数 / 检索语义 / HTTP / SSE）
```

自检用 `StubEngine` 顶替引擎，**不碰语料、不调 LLM**，所以任何机器上都能跑绿。

### 4.2 三个"新人"实测（核心实验）

**方法**：起 3 个全新 AI 会话（不带任何前文），分别扮演前端 / 算法 / 排查，只给任务、不告诉它们仓库里有地图，要求只读不改，事后自报阅读清单。

| 角色 | 任务 | 第一个动作 | 子代理 | 全仓 grep | 自报阅读量 |
|---|---|---|---|---|---|
| 前端 | 加 token 用量展示 + 按用户配参数 | 读 `AGENTS.md` → 契约 §4–§5 | **0** | 0 | ~5 万字符 |
| 算法 | RF 换 2–3 个模型对比并留故事 | `README` → `AGENTS.md` → `hotspot/_index` → `rlr.py` | **0** | 0 | ~4.5 万字符 |
| 排查 | 「多智能体」被拒答，找根因 | `README` → `AGENTS.md` §1 排查行 | **0** | 0 | ~4 万字符 |

结论：

- **3/3 都先读入口文档，并直接命中目标文件**；没有一个去碰 `vendor/`（179k 字符）；没有一次全仓 `grep -r`。
- 阅读量 4–5 万字符是**任务本身跨 4 个模块**的合理成本；省掉的是反复试错与子代理重复读。
- 局限：阅读清单是自报的；且 prompt 要求"汇报读了什么"会轻微促使克制。这是"能走通"的证据，不是严格的 A/B 对照。

### 4.3 测试挖出的 3 个真 bug（已修）

**① Streamlit 前端漏传 `params`**

- 现象：HTTP 用户能调检索参数，Streamlit 用户改了没用。
- 证据：`ui/app.py` 构造 `AskRequest` 时字段列表里没有 `params`。
- 修法：侧栏加「检索参数」面板，**由 `meta.params` 自动生成**（不硬编码参数名），保存到 `settings.json`，随请求带走。

**② 长句检索恒空 —— "库里明明有 MARL，问多智能体却答本库无相关内容"**

- 根因链：`corpus.search()` 是**全词 AND** → LLM 改写出的长句命中 0 → 空 id → 空 body → 模型只能说"本库无相关内容"（**不是 `REFUSE` 分支**，更难查）。
- 证据（合成语料实测）：

```
"multi-agent reinforcement learning methods for cooperative robotics systems"
  旧（AND）  → []
  新（并集） → ['p1', 'p2']
```

- 修法：`Engine._search_union`（拆词 → 逐个检索 → 按命中词数排序取并集），已加回归测试。

**③ SSE 头声明 `keep-alive`，实际写完就关**

- 现象：Windows 下客户端复用已关连接报 `ConnectionAborted 10053`，自检偶发失败。
- 修法：改 `Connection: close`；自检连跑 3 次稳定。

顺带修：`rlr.py` docstring 指向仓库里不存在的导出脚本（实际在外部 dasc 副本），已标注并写明仓库内的替代脚本。

## 5. 怎么用

```bash
# 老前端（过渡期，已改为只调 Engine）
streamlit run scripts/run_ui.py --server.port 8502

# 新前端（HTTP + 静态页）
python scripts/run_server.py --port 8000 --web web
#   浏览器打开 http://127.0.0.1:8000

# 自检（改完必跑）
python scripts/check_api.py
python scripts/check_tree.py --vault .
```

给前端：只调 `GET /api/meta`（建设置页）与 `POST /api/ask`（问答），别 import 算法模块。
给算法：内部随便改，只要 `Engine.ask` 的返回字段还在；新指标加字段即可（只增不改）。

## 6. 边界与红线

1. **前端只准 import `hotspot.api`**（或走 HTTP），不准 import `subcluster` / `retrieval.*` / `reasoning.*` / `schema`。
2. **接口只增不改**：加字段必须带默认值；删/改语义必须换 `CONTRACT_VERSION` 并写迁移说明。
3. 加可调参数 → 只改 `contract.py` 的 `PARAM_SPEC` + `config.yaml`，前端设置页自动出现。
4. 引擎**无会话状态**：历史与每用户 key 都随请求带（前端换 MySQL 账号系统时，服务层不用动）。
5. 热点只能表述为 **铺开 / 新进 / 单会**；永不输出「退潮 / 下降 / 衰退」。
