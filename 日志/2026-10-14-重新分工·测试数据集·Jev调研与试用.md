## 3. 本地 LLM / 微信助手 / Jev 三条新线评估

**本地 LLM**（一台带 12G 显存 + 大内存机器）：
- **配合好**：接"本地 Qwen 14B"只需把 `llm.py` 的 `base_url` 指向 vLLM/Ollama OpenAI 兼容端点，引擎零改动。12G 跑 14B 量化合适；**27B/32B 要 24G+**，12G 硬上会只有 2–5 token/s 不可用。
- 大内存这类机子的**真正大收益是"全库向量拼大矩阵 GPU 提速"**（算法档任务直接受益，现在 8GB 被迫 mmap 按需读）。

**微信助手**：愿景契合（引擎可复用），但**个人微信加群自动回复违反平台条款有封号风险**；合规要走企业微信/公众号/小程序，或先做"聊天窗口仿真演示"。改动量中偏大，放前端 Web 改造之后、共用统一后端接口。

**Jev（TypeSafe System One 决策模型）**：
- 不是本地模型，是**付费云 API**（官方 `$42/Btok = $0.042/Mtok`，只按输入 token 计，输出免费；无本地权重）。
- 定位 = **判别/决策**（Choice/Score/Noul 三原语，带概率+置信度），与"生成"互补。契合点：检索后论文筛选、路由 GLOBAL/LOCAL、引用校验、意图分类——都是"判断"环节，可等价替换调 LLM 的结构化输出，schema 不动。
- **社区复现确存在**（上轮判断"无开源"不准确）：openjev 系 143 仓库。候选：`razorback16/openjev`（703★，DiffusionGemma 26B，需 24G 显存/16G 内存——本机跑不动）；`openJev-verdict-2.0`（294★，151M ModernBERT，**CPU 可跑**）。

## 4. openJev-verdict-2.0 下载与本地试用（本机跑通）

**选择**：`Heman10x-NGU/openJev-verdict-2.0`（151M、JevBench 评测 77.1% acc / 1.44% ECE、Apache-2.0、无需显卡），最符合本机。

**下载**：GitHub 仓库 zip（6.3MB，curl+`-k` 绕过 schannel 证书问题）；**真实权重在 HF 的 `heman10x/rlcd-modernbert-151m`**（605MB `model.safetensors` + config + calibrator + tokenizer）。关键坑：**`transformers` 的 HEAD 下载被拦（OSError offline），但 HF 网页/`resolve` GET 可用** → 用 `urllib` 拉小文件 + `curl -C -` 断点续传拉 605MB，最终字节数精确匹配。

| 问题 | 结果 | 解读 |

## 发现的问题

### 1. 【最严重】本机 HF 网络半通：transformers HEAD 被拦、GET 可用

现象：`transformers` 从 HF 拉模型直接 `OSError: We couldn't connect to 'https://huggingface.co'`，但我用 `urllib`/`curl` 对**同一域名** GET 却能完整下载 605MB。
根因：疑似 HEAD 请求被本机网络/代理掐，GET 放行；`hf_hub_download` 走 HEAD → 全线卡死（这也是早前 bge-m3 联网拉取卡死的同源）。
证据：
```
huggingface_hub.errors.LocalEntryNotFoundError: Cannot find the requested files
in the disk cache and outgoing traffic has been disabled.
```
```
curl -k -C - ... resolve/main/model.safetensors  → 100% (605529340 bytes)
```
**结论**：以后拉 HF 权重不走 `transformers`，用 `urllib`/`curl GET` + 断点续传绕开；HEAD 通道在本机不可依赖。

### 2. `razorback16/openjev` 主模型本机不可跑

DiffusionGemma 26B-A4B 需 **24GB 显存** 或 **16GB+ 内存（MLX）**，本机（8GB/2GB）加载即 OOM。若要用其 API 兼容层，只能借助官方免费宿主 Codiv（100M token 免费）或换小 encoder 模型（verdict/laya）。

### 3. HF 仓库 gated：`heman10x/openJev-verdict-2.0` API 返回 401

现象：`/api/models/heman10x/openJev-verdict-2.0/tree` → 401。
根因：该仓库疑似 gated/私有（README 里的 HF badge 与实际访问不符）。
结论：此次用的是**同作者公开的 `heman10x/rlcd-modernbert-151m`**（Verdict v1.4 引擎对应权重，razorback 也用它）；功能/筛选可用。要严格复现 verdict-2.0 基准数字需作者授权那个 gated 仓库。
