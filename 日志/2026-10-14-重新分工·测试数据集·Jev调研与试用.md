## 发现的问题

### 1. 【最严重】本机 HF 网络半通：transformers HEAD 被拦、GET 可用

现象：`transformers` 从 HF 拉模型直接 `OSError: We couldn't connect to 'https://huggingface.co'`，但我用 `urllib`/`curl` 对**同一域名** GET 却能完整下载 605MB。
根因：疑似 HEAD 请求被本机网络/代理掐，GET 放行；`hf_hub_download` 走 HEAD → 全线卡死（这也是早前 bge-m3 联网拉取卡死的同源）。
证据：
```
huggingface_hub.errors.LocalEntryNotFoundError: Cannot find the requested files
in the disk cache and outgoing traffic has been disabled.
```
```
curl -k -C - ... resolve/main/model.safetensors  → 100% (605529340 bytes)
```
**结论**：以后拉 HF 权重不走 `transformers`，用 `urllib`/`curl GET` + 断点续传绕开；HEAD 通道在本机不可依赖。

### 2. `razorback16/openjev` 主模型本机不可跑

DiffusionGemma 26B-A4B 需 **24GB 显存** 或 **16GB+ 内存（MLX）**，本机（8GB/2GB）加载即 OOM。若要用其 API 兼容层，只能借助官方免费宿主 Codiv（100M token 免费）或换小 encoder 模型（verdict/laya）。

### 3. HF 仓库 gated：`heman10x/openJev-verdict-2.0` API 返回 401

现象：`/api/models/heman10x/openJev-verdict-2.0/tree` → 401。
根因：该仓库疑似 gated/私有（README 里的 HF badge 与实际访问不符）。
结论：此次用的是**同作者公开的 `heman10x/rlcd-modernbert-151m`**（Verdict v1.4 引擎对应权重，razorback 也用它）；功能/筛选可用。要严格复现 verdict-2.0 基准数字需作者授权那个 gated 仓库。
