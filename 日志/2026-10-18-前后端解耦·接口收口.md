## 2. 改造：2 个接口

新增 `hotspot/api/`（L6.5 服务层），编排整体搬出 UI：

| 文件 | 职责 |
|---|---|
| `contract.py` | 契约 v1：`AskRequest` / `AskResponse` / `Citation` / `Topic` / `GraphView` / `Usage` / `MetaResponse`、13 个白名单参数 `PARAM_SPEC`、错误码、stage 事件 |
| `engine.py` | `Engine.meta()` + `Engine.ask()`：意图路径 / 兜底路径 / 追问 / 图谱 / 用量，**无会话状态** |
| `http.py` | 标准库 `http.server`：`GET /api/meta`、`POST /api/ask`（JSON 或 SSE）、`/api/health`、静态托管、CORS。**零第三方依赖** |
| `../scripts/run_server.py` | HTTP 入口 |
| `../scripts/check_api.py` | 离线自检：契约往返 + 参数校验 + HTTP/SSE 冒烟（StubEngine，不碰语料） |
| `../web/index.html` | 最小参考前端（原生 JS，无构建）：设置页由 `meta.params` 自动生成，SSE 画进度 |

前后对比：

| | 改造前 | 改造后 |
|---|---|---|
| 前端要认识的模块 | 11 | **0**（只 `from hotspot.api import Engine` 或走 HTTP） |
| 前端要认识的符号 | 19 | **2**（`meta` / `ask`） |
| 前端要认识的内部结构 | 6 + 2 种磁盘格式 | **0**（引用已 deref，图已摊平成 nodes/edges） |
| 两套前端是否共用逻辑 | 否（要各写一遍） | **是**（Streamlit 与 HTTP 同一个 `Engine`） |

响应里几个"省前端事"的决定：

- `answer.citations[]` 直接带 `title` / `venue` / `year` / `arxiv_url` ⇒ 前端**不用再查语料**；
- `topics[]` 是结构化字段（原来是一段拼好的 markdown 字符串）⇒ 排版归前端；
- `graph` 只给 `nodes/edges`（`chain` / `cite` 两种边）⇒ 原来 UI 里的 plotly + DOT 两套画图代码删掉；
- `usage` 带实测 token（`tokens_in/out`、`cache_hits`、`cost_yuan`、各阶段耗时）⇒ token 用量统计有数据源了。

## 3. 顺手修掉的四个问题

| # | 问题 | 证据 | 处理 |
|---|---|---|---|
| 1 | 兜底路径的关键路径**从来没生效**：`ui/app.py:_maybe_keypath` 写的是 `from .subcluster import _run_mps` | `hotspot/ui/` 下没有 `subcluster.py`，`ImportError` 被外层 `except` 吞掉 | 搬到 `engine.py` 后改为 `from ..subcluster import _run_mps` |
| 2 | 意图路径的簇引用用**序号**而不是 `cluster_id`（`[C:0]` 指第 0 个簇） | 同文件 `cards.append(f"[C:{i}] ...")`，与兜底路径/卡片文件的 `[C:<cluster_id>]` 两套口径 | 统一为 `cluster_id`，`citations` 与 `topics` 因此能对上 |
| 3 | 答案生成的 token 用量统计不到：`generate_answer` 内部又 `make_client` 建了个新 client | `reasoning/answer.py` 原签名 | 加可选 `client=`，服务层复用同一个 client，usage 差值才算得准 |
| 4 | 追问只折对话文本，**不带前文检索到的论文** | 旧 `_follow_up` 只拼 `用户：…/助手：…` | 请求里带 `history[].citation_ids`，服务层把这些论文摘要重新并进上下文（`followup_papers` 可调） |

## 发现的问题

1. **【最严重】意图路径没有跑过真数据**。本机无 G 盘语料、无 key ⇒ `parse_query → subcluster_adaptive → 命名 → 校验` 这条只在代码层审过，没实跑。**上线前必须在 `测试数据集/` 或 G 盘上跑一次**，重点看 `topics` 的 `cluster_id` 与 `citations` 是否对得上（这正是本次改口径的地方）。
2. **SSE 没做断线重连**。前端断开后引擎会继续跑完（省得白烧 token），但结果丢失；前端需自行重发（LLM 有缓存，重发安全）。
3. **Streamlit 只在 bare mode 跑过 `main()`**（无异常、无渲染错误），没开真服务点过按钮；`st.rerun()` 后的会话恢复未实测。
4. **`api_key` 经 HTTP 明文传输**。当前只适合本机/内网；公网必须挂 HTTPS + 网关鉴权（引擎里**不要**加鉴权逻辑，那是前端/运维的活）。
5. **`_name_clusters` 仍是串行 LLM 的接口形状**（6 个簇并行、worker≤6）：簇多时命名阶段仍是主要耗时，算法侧可考虑合并成一次调用（但这会改 prompt，留给算法同学评估）。

## 5. 追加：给 AI 的入口做成"路由表"（19:10）

**问题**：队友的 AI 进仓库常常找不到东西 → 起 1–3 个 Explore 子代理 → 每个子代理各读一遍
README/索引/大文件，token 主要烧在"探索"而不是"做事"。

**根因（四个，都可量化）**：

| 根因 | 证据 |
|---|---|
| 入口是"叙事"不是"路由" | 旧 `AGENTS.md` 只有 1.4k 字符、讲权限与回写，没有"改 X 该读哪几个文件" |
| 仓库存了 407 个 LLM 缓存 JSON | `git ls-files` 计数 = 525，其中 `vendor/dasc/_out/llm_cache` 406 个 + egress 1 个；任何 `grep -r` 先被它们淹掉 |
| 大文件没有骨架指引 | `engine.py` 839 行 / `contract.py` 574 行，agent 倾向整篇读 |
| 不同工具入口不同 | Claude Code 找 `CLAUDE.md`、Cursor 找 `.cursorrules`，都不认 `AGENTS.md` |

**做法**：

1. `AGENTS.md` 重写成 **3.9k 字符的路由表**：9 类任务 × 「只读这些 / 读完就停」+ 禁读清单（vendor 179k 字符、workspace、`_out/`）+ 大文件的 grep 入口 + "别为找东西起子代理"的显式规则 + 两条自检命令。
2. 9 个 `_index.md` 顶部各加 1 行「给 AI：这块只读 X」。
3. `.gitignore` 掉 `hotspot/vendor/dasc/_out/`，`git rm --cached` 掉 **407 个文件**（本地文件不删，dasc 照常命中缓存）。跟踪文件 525 → 118。
4. 加 `CLAUDE.md`（`@AGENTS.md` 导入）与 `.cursorrules` 两个 5 行别名，内容只有指针，不复制规则。

**效果（实测字符数，按 3 字符/token 粗估）**：

| 场景 | 旧 | 新 |
|---|---|---|
| 跟踪文件数 | 525（77% 是缓存 JSON） | **118** |
| "改接口"要读的量 | 77,939 字符 ≈ **26k token**（且不含子代理探索） | 18,094 字符 ≈ **6k token** = AGENTS + 契约文档 §3–§6 + contract 的 DTO 段 + `Engine.ask` 段 |

**做不到的部分（诚实说）**：路由表只能**降低起子代理的动机**（找不到东西才探索），
不能强制任何 AI 工具不调用子代理；也没法约束队友的 prompt。能保证的是：**照表读就够了**。


## 6. 实测：三个"新人"用路由表接手（19:22）

**方法**：起 3 个全新的 agent 会话（不带本对话上下文），只给任务、不告诉它们仓库里有地图，
要求**只读不改**，事后自报阅读清单、是否起子代理、是否全仓搜索。

| 角色 | 任务 | 第一个动作 | 子代理 | 全仓 grep | 自报阅读量 |
|---|---|---|---|---|---|
| 前端 | 加 token 用量展示 + 按用户配参数 | 读 `AGENTS.md` → 契约文档 §4–§5 | **0** | 0（grep 都限定在单文件） | ~5 万字符 |
| 算法 | RF 换 2–3 个模型对比并留故事 | 读 `README` → `AGENTS.md` → `hotspot/_index` → `rlr.py` | **0** | 0（`find` 2 次都 `maxdepth`） | ~4.5 万字符 |
| 排查 | 「多智能体」被拒答 | 读 `README` → `AGENTS.md` §1 排查行 | **0** | 0（4 次 grep 带 `--include` 且排除 vendor） | ~4 万字符 |

三个人都明确说「AGENTS.md 的按任务查表有帮助，省掉整仓翻找」。**没有一个起子代理**。

### 但它们挖出 3 个真问题（已修 2 个）

1. **Streamlit 前端根本没把 `params` 传进请求**（`ui/app.py:360` 构造 `AskRequest` 时漏了字段）。
   HTTP 用户能调参数、Streamlit 用户不能——同一套引擎两个待遇。已补：侧栏「检索参数」面板
   **由 `meta.params` 自动生成**（不硬编码参数名），保存到 `settings.json` 的 `params`，随请求带走。
2. **`corpus.search()` 是全词 AND**，而 `_ask_legacy` 的 LOCAL 路径直接拿 LLM 改写的整句去搜。
   实测：`"multi-agent reinforcement learning methods for cooperative robotics systems"` → `[]`。
   于是「多智能体」这条链一路空到模型嘴里，输出"本库无相关内容"（不是 `REFUSE`，是空上下文）。
   已加 `Engine._search_union`（拆词 → 逐个检索 → 按命中词数排序并集），实测同一句召回 `[p1,p2,p3]`。
3. `hotspot/rlr.py` docstring 指向 `dasc/rlr/export_future_rf.py`——**仓库里没有**（在外部 dasc 副本）。
   已标注，并写明本仓库唯一的训练脚本是 `scripts/export_future_rf_arxiv.py`。

另外把两条实测教训写进 `AGENTS.md` §3：`find .` 会数出 633 个（未跟踪产物），要用 `git ls-files`；
`corpus.search` 的 AND 语义坑。

**结论**：路由表能消掉"探索成本"，但消不掉"任务本身跨 4 个模块"的阅读成本（4–5 万字符是合理的）。
真正省下的是反复试错与子代理的重复读。
