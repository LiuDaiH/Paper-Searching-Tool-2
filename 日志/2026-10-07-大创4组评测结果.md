## 2. 本次修复

- **`run_eval.py`**：专项统计 `(r.get("meta") or {}).get("key_path") or {}` —— 原来
  `.get("key_path", {})` 在 `meta["key_path"]=None` 时报 `AttributeError: 'NoneType' object has no attribute 'get'`。
- **gymna_env 确认**：py3.9 下 openai 1.109 已装（此前 `No module named 'openai'` 是解释器切换问题），
  仅剩 sklearn 1.6.1 版本警告（可忽略）。

## 发现的问题

### 1. 【最严重】`run_eval` 在 `key_path=None` 时崩溃

现象：全量 70 题跑中 `AttributeError: 'NoneType' object has no attribute 'get'`（小样本 8 题不触发）。
根因：专项统计对 `meta["key_path"]` 为 `None`（未算关键路径的题）用了 `.get("key_path", {})`，
值存在但为 None 时返回 None 再 `.get("feasible")`。
证据：`AttributeError: 'NoneType' object has no attribute 'get'`。
结论：改为 `.get("key_path") or {}` 安全处理，编译通过，小样本 g0 验证 `refuse_recall=1.0`。

`gymna_env`（py3.9/sklearn 1.6.1）与 `D:\Ana_`（py3.13/sklearn 1.7.2）并存：
`future_rf.pkl` 由 1.7.2 导出，1.6.1 加载有版本警告（数值略偏、不崩）。
建议在 ≥3.10 环境跑（本轮用 `D:\Ana_`），或接受警告。
