## 2. MPS 卡死根治（从"线程超时"到"算法内预算"）

评测 G0–G3 时关系题 `rel05` 等卡死到你 `Ctrl+C`（`KeyboardInterrupt`）。

- **根因**：`dasc/mps` 的 `gtest/cl/ideal` 对稠密大图做理想/秩计算，`_mag_iterate`×位置×全元素，
  组合爆炸且无超时；`KeyboardInterrupt` 是 `BaseException`，subcluster 的 `except Exception` 捕不到。
- **修法**：
  - `dasc/mps/core.py`：加 `MPSBudgetExceeded` + `budget_clock`，`gtest/cl` 每次检查时间预算，超时即抛。
  - `hotspot/mps.py`：`compute_key_path` 设 `MPS_TIMEOUT=30`（环境变量可调），捕获转为「未运行」
    （`feasible=False` + note），线程正常返回、不留后台空转。
  - `subcluster.py`：`_run_mps` 线程超时(45s)作第二道保险。
- **验证**：400 篇大输入默认 30s 预算下 3.7s 正常算完；强制 `MPS_TIMEOUT=0.001` 则 0.27s 返回降级结果。

## 3. 评测修复与专项指标

- `dasc/llm/client.py`：网络/5xx/429 类错误**重试 3 次**（`DASC_LLM_RETRIES`），不再一次失败即崩。
- `eval/run_eval.py`：
  - 空答案（端点被吞）标记为 `error`，不污染指标；
  - 修 `_mean` 对空 metrics 的 `KeyError`（`.get` + 跳过）；
  - 修 refuse 口径：`本库无相关内容` 等文本也算正确拒答；
  - 新增专项指标 `rlrag_produced / key_path_feasible / rlrag_top10_hit_rate`（`Answer.meta` 透传）。
- 4 组 70 题结果：端点稳定后无空答案；`local` 引用支撑最优(0.78–0.81)，
  `global` 较弱(0.5–0.57)；大创开关对 4 项标准指标影响小（其只输出附加排序，不改变事实性指标）。

## 发现的问题

### 1. 【最严重】MPS 在稠密大图上卡死（已根治）

现象：评测关系题卡住直至 `Ctrl+C`；栈停在 `_mag_iterate`→`poset.ideal_of`/`gtest`。
根因：无时间预算 + `KeyboardInterrupt` 不被 `except Exception` 捕获。
```
File "...\dasc\mps\algorithms.py", line 163, in _mag_iterate
    K_i = mps.cl(alpha[:i])            # cl/gtest 每次对全元素计算
KeyboardInterrupt
```
**结论**：算法内 30s 时间预算 + 捕获 `MPSBudgetExceeded` 转降级，根治卡死。

### 2. 环境不一致

`gymna_env` 为 py3.9，装不了 sklearn 1.7 且缺 `openai` → 满屏 InconsistentVersionWarning + 部分题
`No module named 'openai'` error。修法：gymna_env `pip install openai`（sklearn 警告可忽略），
或改用 py3.13 环境（sklearn 1.7.2 + openai 已装）。`requirements.txt` sklearn 下界放宽到 >=1.6。

### 3. 相对语料路径未按项目根解析

`corpus.sources` 相对路径直接 `Path(s)`（按 cwd），导致样例快照读不到自身 workspace。
修：`corpus.py` 把相对 `sources`/`arxiv_source` 解析到 `HOTSPOT_ROOT`（兼容绝对，利于换机）。
